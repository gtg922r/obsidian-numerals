## First Reading admission

`native-ordering.plan.json` uses one window and leaf, opens the synthetic ordering note, requests Reading mode, and reveals three physical source lines through public `MarkdownView.setEphemeralState`. Opening, setting a mode and revealing a line are **direct API setup**, not proof of native user interaction. The two identical `$f(2)` spans expect 14 and 16 respectively; the later `$x+1` expects 6. Sequential current samples accommodate native virtualization. They do not imply simultaneous visibility; a changed owner/source/index/snapshot/settings generation across those samples downgrades their combined coverage.

The instrumented observer retains the actual before-native code element, original text, context/path and `getSectionInfo(code)` capture. Revisited transformed code preserves the original capture. Current reads require:

- The requested leaf and the current Editor, TFile, view, document/window, complete Editor/view buffer and vault file identity, checked around each synchronous read.
- A complete native section source match and exact physical UTF16 span. The first admission is deliberately limited to a singleton one-line, single-backtick code span in its section. Embeds, CM/pre content, containers, ambiguous sections and unaccounted current code nodes cannot satisfy it.
- The existing public G source/index/state/snapshot and source/settings generations. The outer `getEditorSnapshot` wrapper may reallocate; retained sourceId/index/state/snapshot identities must agree. No evaluation or formatting method is invoked by sampling.
- Exactly one connected, visible `.numerals-inline-value` with visible ancestors and no inline error. A visible code wrapper cannot prove its hidden result is visible. Wrong stable current numeric/rendered values fail promptly.

Observer-absent controls use the pinned native implementation detail `previewMode.renderer.getSectionInfo(element)` and `renderer.lastText`, combined with complete current source and owner checks. This is **not a public API**. Missing or ambiguous native section evidence is `UNAVAILABLE`. The unchanged-candidate control checks the current rendered value without reading any evaluator seam; the Numerals-disabled control requires raw source code and no loaded Numerals plugin. They run separately in fresh profiles when authorized.

`settleCurrent` samples structural readiness and identity at bounded intervals (default 100 ms, at least 250 ms stable, at most 10 seconds), then takes a fresh seal read. Pending/unavailable state, a changed generation or a changed DOM identity resets the interval. It settles valid structural failures as well as successes, so it does not poll until the expected answer happens to appear. Offline replay checks explicit numeric timing fields, ordered point reads, the stable suffix and final seal, exact plan/action/owner binding, and matching journal records. Later observed pending/settings/snapshot changes in that action invalidate the seal. Timeout/interruption retains sampled evidence and cannot become a pass.

TeX samples require the intended current MathJax output and record available host/API/MathJax versions. The public completion function is not invoked merely to observe because it alters the rendering queue. There is no DOM generation stamp; equal stable DOM does not prove it was produced by a particular evaluation. The report never claims all pending work drained or derives evaluation counts from snapshot notifications. Plain-value ORD-01 admission does not establish TeX/native UI coverage.

Every assertion refers to its explicit action and sample. Successful assertions still leave ORD-01 `PARTIAL`: the full catalog row includes additional behavior. Legacy `observed-dom-text`/`observed-numeric-result` only report historical `OBSERVED`/`NOT_OBSERVED`; `dom-text`/`numeric-result` remain unavailable. Historical `ordering.plan.json` is not dispatchable for first current-state acceptance.

## Ownership, writes and evidence

Instance-only Editor/Vault/DataAdapter wrappers call the original once with identical receiver/arguments/callbacks, preserve exact return/promise/throw behavior and add no promise handlers. Restoration receipts detect replacements. The CM extension only observes native events and updates; it adds no decorations, dispatch/filter/extender/history changes or synthetic events. Trusted input needs same-view/state/change correlation. `one-write` requires an explicit action, one wrapper session and transaction ID, the same editor/window, and ordered start → CM change → end with complete buffers. Absence of wrapped calls is not proof of all filesystem writes being absent.

The controller permits one owned app/profile/vault, at most two windows and six editors, bounded events/bytes/deadlines, and loopback CDP. The first plan uses one window/leaf. Existing-pane actions check current ownership before/after focus callbacks and async work. A popout requires returned-leaf/window/nonce proof; URL/title cannot authorize input. Targeted splits remain refused pending a native driver. Abort starts owned-process termination independently of pending work. Profile preparation runs in an owned child beneath scratch without changing HOME. Cleanup attempts every owned registration/wrapper/bridge/component and requires a mode-specific disposal receipt plus confirmed process exit; gaps invalidate strict claims.

Exports are limited to `results.json`, `provenance.json`, `selection.json` and `sha256.json`. These include bounded action/current-sample evidence, passive observations and deduplicated synthetic disk bytes. Original/saved BOM/CRLF bytes remain distinct from Editor strings; the only captured settings file is fixture Numerals `data.json`. No personal vault/profile dump, credentials, browser storage, raw stacks/environment/process logs, arbitrary settings or private packet is uploaded. Refusal evidence does not echo unaccepted selection text. Immediate disk samples do not prove autosave settled or exclude transient writes.
