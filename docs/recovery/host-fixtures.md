# Official Linux extraction fixtures

The `Obsidian extraction fixtures` PR workflow runs only on fresh GitHub-hosted Ubuntu 24.04 runners. It first captures four smoke sources, then all 95 synthetic sources in both Reading and Live Preview (190 case/mode results). It loads one local recorder, not Numerals. This establishes host extraction observations for parser comparison; it does not establish calculation correctness, installed-artifact acceptance, minimum-version, macOS, mobile, or early-access compatibility.

`host-tests/fixtures/sources.json` preserves the original NQ13A pack's 95 UTF-8 source hashes. Its canonical cases hash is `fbb224c760608883a222b02ef6e414b9d38221f042b3b7f7dc6dce9ae1c55a69`. Notes are materialized from JSON to preserve CR, CRLF and astral characters independently of checkout line-ending settings. The separate support catalog exports and hashes the embed target, local link target and positive control. All support files are verified before and after each case; only declared embed fixtures can produce callbacks from `Other.md`.

The recorder contains no proposed parser results. Native callbacks retain raw registered-block bodies, code text, relative context source paths, opaque per-run document identity and nullable section information. Every event distinguishes requested mode, operation phase and observed active-view identity. Native origin is established from callback/context containment in known CodeMirror roots or the Reading preview container, with DOM ancestry recorded; unmatched/detached callbacks remain unknown. Hidden CodeMirror widgets can call handlers while a Reading view opens, so requested mode and current view mode alone never establish Reading origin. Only proven Reading callbacks after opening satisfy its extraction gate. Raw transient/unknown occurrences remain available. Live Preview callbacks are optional because visibility and selection can withhold them. Actual CodeMirror trees/documents are separate; original disk bytes remain authoritative while the observed editor removes a leading BOM and normalizes line endings to LF.

The isolated helper uses its own package/lock and Node 24. `npm ci --ignore-scripts` and `npm test` in `host-tests` are safe locally; `npm run capture` refuses local execution. Never run a second local Obsidian process, native CLI or protocol action to collect these fixtures. The controller requires the GitHub-hosted Linux environment, uses Xvfb, binds CDP to loopback and gives the app an explicit environment without GitHub/runtime credentials. HOME is preserved. One fresh profile registers one marked synthetic vault with updates disabled; core plugins and remote plugin installation are excluded. This is process/profile isolation on a disposable runner, not a network sandbox.

`inputs.json` pins official public Obsidian 1.13.7 asset URLs, release/asset IDs, sizes and SHA256 digests. Download hashes are verified before data extraction or executable launch. The decompressed application also has a pinned hash. Launcher 3.2.0 is locked by npm integrity and uses an explicit local version descriptor plus the verified app path; its unchecked default download routes are unused. Its pinned 7z helper extracts the verified AppImage without FUSE. Only the ephemeral Linux app uses `--no-sandbox`.

Each operation guards canonical vault name/path, a generated marker and catalog bytes. Sources are hash-checked before and after capture. Real block/inline positive controls bracket each surface, with their actual events validated. Every fixture must open the exact file and mode, settle for 600 ms after at least 800 ms, and complete the entire opening/capture operation within five seconds. Native-empty declarations require a Reading section and a completed native `MarkdownRenderer.render` call on the same bytes with separately recorded empty extraction. Live Preview requires a complete actual tree and normalized document. Startup, capture, controller and workflow have independent deadlines. Callback errors are latched as failures. Each case has independent diagnostic identity established before source guards, and a cancellation token checked after every host await. Timeout/unload invalidates the token so delayed host promises cannot resume recorder operations; an already-requested host operation itself is not cancellable. Owned process groups, plugin subscriptions, render children and timers are disposed on completion/failure; termination uses the same diagnostic finalizer.

Artifacts contain only `capture.json`, `sources.json`, `support-sources.json`, `provenance.json`, `diagnostics.json` and `sha256.json`; failed runs may contain only diagnostics/provenance/hashes. No profile, browser storage, vault configuration, environment dump or raw process log is uploaded. Provenance distinguishes tested PR head from workflow merge commit, records input/helper/recorder/support hashes, run identity and requested coverage. Download artifacts, verify every listed file hash and exact head, then compare raw observations against the candidate index. An empty or incomplete capture cannot pass. Owner review is required before using observations as golden expectations or accepting the parser; only the owner merges. This workflow cannot publish or modify releases.

The initial run `34776649635` is provisional: its 190 results revealed native-empty cases 020, 021 and 052 and leading-BOM normalization in case 043, but its requested-mode labels cannot prove callback origin. Its raw smoke case 001 is retained solely as a regression input proving that removing actual Reading callbacks while leaving the hidden CodeMirror callback must fail. It is not an accepted parser oracle.

Run `npm test` in `host-tests` for guards, byte preservation, coverage, mode/tree, provenance, allowlist and environment failure checks. Run the unchanged root `npm run check` separately. CI execution and downloaded evidence verification remain required before host acceptance.
