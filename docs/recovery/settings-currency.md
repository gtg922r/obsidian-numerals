# Settings and currency lifecycle (Package E)

Obsidian 1.13.0 is the minimum. One `getSettingDefinitions()` implementation provides native settings rows and global search; there is no legacy `display()` path. The five currency/TeX controls remain present alongside every existing setting. Currency mappings open a local draft modal with explicit Save, Cancel and Remove mapping. A partial form never saves.

## Stored settings

`src/settings/normalization.ts` is the storage boundary. It returns a complete detached value, deep-copies nested mappings, validates types/enums/integer ranges, and migrates both numeric `layoutStyle` and older `renderStyle`. Unknown stored fields do not become executable settings. Valid saved code/symbol preferences are preserved; missing or invalid preferences default to symbols. Currency-standard precision and custom precision of two decimal places remain defaults.

Empty inline triggers disable their mode. Overlapping prefixes remain valid and retain longest-prefix matching. Exact duplicate nonempty values are rejected during edits. On load, saved strings precede missing defaults; the first saved duplicate in result/equation/TeX-result/TeX-equation order wins and later duplicates are disabled. Invalid currency symbol metadata is reconstructed from the validated Unicode code point, not trusted from storage.

## Transaction and change boundary

`SettingsController` serializes edits against the latest successful state. It validates the whole candidate and prepares its runtime/formatter before persistence. A persistence failure discards the candidate; the active settings/runtime and their generations stay unchanged. Successful persistence swaps the prepared references synchronously, then publishes one typed change. Subscriber failures are reported without breaking settings persistence. A cold-load currency conflict preserves the normalized saved mapping, exposes a configuration error to settings and later note contexts, and blocks calculations until repaired; it does not silently activate a different mapping. Queued edits and pending plugin-load continuations cannot activate after unload. A cold configuration error produces one concise load notice and visible calculation diagnostics; settings remain registered for repair.

`NumeralsPlugin.getRuntimeContext()` returns the current `NumeralsRuntimeContext` (`engine`, `formatter`, `preProcessors`, `currencyMap`, `currencyGeneration`, `currencyWarnings`, optional `configurationError`). Retain this exact context with raw evaluation snapshots. `subscribeSettingsChanges(listener)` returns an unsubscribe function; register it with the owning host component. `settingsGeneration` and `evaluationSettingsGeneration` expose initial/current counters. `updateSettings(patch)` and `saveSettings(patch)` share the same transaction; `settings` reads return detached committed snapshots.

The public subscription exposes changed keys, `evaluation`, `presentation`, and `suggestions` effect classes, a total generation and an evaluation generation. Mapping, trigger, inline-enable, cross-note and frontmatter changes affect evaluation. Formatting/layout changes affect presentation only. Suggestion changes do neither. F/G must use evaluation generations to invalidate cached evaluations and pending insertions, while formatting changes reformat retained raw values without rounding the scope.

## Currency runtime

The owner-approved architecture uses complete private `create(all)` mathjs instances. Candidate construction never patches mathjs's shared default namespace. Only the private parser and Unit alphabet hooks recognize the active currency symbols. All names are preflighted; conflicting canonical codes or required symbols fail with guidance, never `override: true` or catch-and-ignore.

A conflicting optional lowercase alias is omitted with settings guidance (physical `cup` remains volume while `CUP` can be currency). Reserved mathjs names cannot become canonical currency codes. Invalid saved currency configurations stay visible in settings and block evaluation with guidance until a valid Save or explicit Remove repairs them.

Currency mapping commits rebuild the engine and discard ad-hoc `createUnit` definitions and executable scopes; declarations must be reevaluated from source. This does not resolve repeated user declarations (#175), which remain visible collisions. Removed custom currencies disappear unless still configured by another mapping. Existing currency codes are independent dimensions, not exchange rates.

The runtime gateway is limited to calls already used by the current evaluators/formatters. Arbitrary expression functions remain available through `all`. Unused retired engines can be collected; a weak engine-keyed ownership map retains cleanup while a formatter/context still needs its engine. Each result formatter retains the engine that created its registry; future snapshots must retain the engine and formatter together. Never mix raw Units/functions from different engine generations. Retained formatters use their captured engine explicitly; formatting never switches global runtime bindings.

Currency TeX uses validated literal Unicode escapes rather than globally installed MathJax macros. Pure currency display defaults to configured symbols, canonical insertion retains currency codes, and compound units retain existing precision/code policy. Arrays, matrices, native ResultSets (including semicolon-row results), and plain objects retain their existing container serialization while contained currency aliases use canonical codes. ResultSet entries are rebuilt through its public constructor without serializing raw numeric values. Valued currency Units use public conversion with original formatting flags restored, preserving exact normalized BigNumber values; valueless Units remain valueless. D's scanner now maps complete unquoted prefix/suffix amounts and standalone symbols back to full original UTF-16 token spans. Prefix amounts can contain grouped commas inside calls/lists; native suffix forms preserve call/list/index commas (`[1,234$]` remains two elements). Names such as `$price` and `foo€`, references, strings and comments remain protected; malformed top-level amounts are not partially normalized. Native aliases support supplementary currency code points and protected quoted forms such as `unit("1$")`, `unit(1,"$")`, and `number(1 USD,"$")`.

## Dependency/API evidence

Verified on 2026-09-13: [official npm Obsidian typings](https://www.npmjs.com/package/obsidian) latest 1.13.1 and [official Obsidian linter](https://www.npmjs.com/package/eslint-plugin-obsidianmd) 0.4.2. Both are pinned exactly. The TypeScript library list additionally includes `ES2021.WeakRef` for weak lifecycle ownership; compilation targets and strict checks are unchanged. The declarative definitions, binding hooks and refresh APIs used here are marked `@since 1.13.0`; `Modal.setTitle` predates the floor. The [official settings documentation](https://github.com/obsidianmd/obsidian-developer-docs/blob/main/en/Plugins/User%20interface/Settings.md) confirms that overriding `setControlValue` replaces its default mutation and automatic save, so the override explicitly uses the shared transaction.

Mathjs public API evidence: [private instances](https://mathjs.org/docs/core/configuration.html), [units and aliases](https://mathjs.org/docs/datatypes/units.html), and [parser customization](https://mathjs.org/docs/expressions/customization.html). Both alphabet hooks are public typed mathjs APIs; only private engines are customized, including UTF-16 pairs for supplementary currency symbols.

## Verification boundary

Behavior tests cover normalization, all settings definitions, triggers, modal submission/cancel/remove/errors, atomic persistence, native currency forms, remapping/removal/reload, and mathjs breadth. These Node/jsdom tests do not establish actual Obsidian settings search, popout, desktop/mobile or installed-artifact behavior. Host QA is deferred to I; no Obsidian launch or personal vault/plugin write is part of E. Only the owner merges and publishes BRAT prereleases; stable 1.10.2 metadata is unchanged.
