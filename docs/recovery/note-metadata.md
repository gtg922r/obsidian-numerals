# Note metadata capture and provenance

`src/evaluation/metadata.ts` captures declarative inputs for a new evaluation session. The host supplies a complete authoritative buffer (`sourceId`, `revision`, optional `path`, and `text`), its owning mathjs runtime, and a YAML parser callback. Capture performs no math evaluation or host reads. Expressions and function-key declarations remain source strings for the session to evaluate in a fresh scope. It never imports an older populated scope.

Own frontmatter comes directly from that buffer. Its `numerals` property controls opt-in, including the existing all/none/single-key/list policies and force-all fallback. Dollar-prefixed fields remain available regardless of that policy. Current YAML values always win: Dataview cannot replace them, their canonical-name families, or the source opt-in policy. Deleted YAML fields, including dollar globals, cannot return from an older page projection.

A projection defaults to `origin: 'page'`, because Dataview's public page result combines YAML and inline fields. The [current page serializer](https://raw.githubusercontent.com/blacksmithgu/obsidian-dataview/master/src/data-model/markdown.ts) also exposes a raw YAML object at `file.frontmatter`. The [public metadata documentation](https://blacksmithgu.github.io/obsidian-dataview/annotation/metadata-pages/) describes an older list of `key | value` strings. Capture reads this public field through own data properties before stripping `file` from evaluation inputs. It accepts a complete plain mapping, including a null-prototype mapping, or an unambiguous legacy list. Empty `{}` or `[]` means a known empty YAML key set; missing, inherited, accessor, malformed, or ambiguous data does not. Multiple legacy separators or surrounding whitespace on a legacy key make the list ambiguous, so the complete list is rejected rather than trusting a partial key set.

The cached YAML key set identifies deleted YAML fields and their canonical aliases, which are quarantined. Other page fields may supplement the current source only when this complete key set is available. Without it, the remaining page overlay is ambiguous and is quarantined too. Exact evidence tying the projection to the complete buffer can supply the YAML key set from successfully parsed source when public page provenance is unavailable. Current source values still take precedence. If a page's cached YAML data contradicts that evidence by retaining deleted fields, capture quarantines them and downgrades freshness to `unverified`.

An adapter may explicitly declare `origin: 'inline-fields'` only when its provider truly supplies separately captured inline fields; relabeling the combined page result is invalid. These distinguishable inline fields can supplement current YAML, with canonicalized duplicate cleanup and final-array-item interpretation for repeated fields. They remain unverified and insertion-ineligible without exact buffer evidence. `quarantinedFields` and actionable warnings name excluded page fields. Native entries remain separately available, including while Dataview is pending or entirely quarantined. No cached JavaScript function is accepted, even inside a collection. Accepted inputs are detached with the injected runtime's value-ownership helper.

Dataview has four capture outcomes:

| State | Inputs available | Metadata permits automatic insertion |
| --- | --- | --- |
| `native-ready` | Native entries immediately; Dataview absent | Yes, subject to all source and generation guards |
| `pending` | Native entries immediately | No |
| `unverified` | Native entries and eligible inline projection entries; ambiguous fields quarantined | No |
| `verified` | Native and combined entries | Yes, subject to all source and generation guards |

Pending uses a caller-supplied monotonic clock and a deadline rooted at the original request start. Its default bound is 250 ms, with an absolute cap of 5 seconds. Invalid or missing clock data expires immediately to `unverified`. Hosts must retain the same request start while awaiting one capture; repeatedly restarting pending on each read defeats any bounded policy. No state prevents native mathematical evaluation. Calling without Dataview explicitly selects native-only operation and does not leave notes pending.

Mtime, native metadata events, and Dataview index revisions are invalidation signals, never exact-buffer provenance. The ordinary Dataview page API does not prove that its projection represents the live editor buffer. An adapter may supply `ExactDataviewBufferEvidence` only if its provider can actually attest the projection's captured full text, source/buffer identity, source revision, path, and projection revision. The helper checks every field, including full text. Constructing this evidence from matching timestamps or revision labels is invalid. A changed buffer fails the gate even if its revision label was accidentally reused.

`entries` can contain distinguishable Dataview inline values whose content is unverified. Every such entry identifies its provenance, and `nativeEntries` provides the immediate fallback. Capture's `projectionUsed` reports whether accepted entries actually include Dataview values. Quarantining the entire overlay does not promote freshness: it remains `unverified`, even if only native entries remain. Consumers carry capture's final freshness onto the snapshot. The note session tracks actual reads and withholds insertion for dependent rows, including calls through defining functions and previous/total helpers. Independent constant or native-only results remain eligible. `getMetadataFreshness` performs only the initial evidence check; consumers should use capture's final status after quarantine. `allowsAutomaticInsertion` describes the projection's metadata prerequisite, never whole-note or source-write authorization.

The concrete service uses a bounded deadline with the same monotonic clock origin as `pending.startedAtMs`. It evaluates native inputs immediately. Pending and expired states contain identical captured native entries, so expiry changes only metadata status and its diagnostic; it preserves the mathematical generation, recorded results and each row's eligibility. A ready result is republished as a fresh snapshot object without repeating `random()`, `createUnit`, metadata initialization or any other mathematics. If evaluation is still pending, its one result receives the final status before publication. An error is not retried by the timer. This transition does not reread mutable provider data. A repeated base request cannot restart the expired deadline; new provider metadata must arrive with a new metadata revision and receives a new evaluation. Source replacement, invalidation and disposal cancel the prior deadline.

Frontmatter parsing currently recognizes a leading `---` header, optional BOM, LF/CRLF/CR line endings, and `---` or YAML `...` closing markers. Missing, malformed, nonmapping, or unclosed metadata never falls back to old cached fields. The accepted Obsidian 1.13.7 Linux source fixture capture covers these forms; open headers intentionally remain conservative exclusions despite permissive native Reading output. See [source-index.md](source-index.md) for evidence and the limited compatibility claim. Metadata provenance tests do not establish host lifecycle behavior. No host launch or live-vault work is part of this implementation.
