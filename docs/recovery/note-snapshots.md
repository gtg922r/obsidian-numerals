# Note snapshots and service ownership

Package F separates a complete note generation from its visible occurrences. The standalone index supplies physical source order; an evaluation session owns that generation's native mathjs scopes and closures. The service shares a completed snapshot with consumers by buffer identity, separately retaining the note's file path. Embedding adapters should request the target note's complete generation and project its selected occurrences; they must not import target globals into the host note.

## Result ownership

`valueOwnership.ts` copies metadata inputs and immediately recorded result payloads with public mathjs APIs. This is an ownership boundary within trusted evaluator code, not an immutable wrapper over every native mathjs object. BigNumbers require their public constructor because `math.clone` returns the original object. ResultSets use their public constructor and recursively copied entries because `math.clone(ResultSet)` throws. Matrices use public writable construction and element traversal so nested ResultSets and immutable index matrices remain valid. Unit copies retain raw numeric precision, offset/prefix/simplification behavior and the originating registry. They are never moved to a different engine.

Native Unit methods can create new objects that refer to that registry even if an initial component record is copied. The service therefore keeps typed backing values private and gives surfaces data-only descriptions and controlled formatter output. It does not freeze shared unit definitions, patch private internals, or claim that a native clone is an adversarial isolation boundary. Functions become non-callable descriptions, including functions nested in arrays, objects, matrices and ResultSets. Opaque class instances become descriptions. This does not restrict which functions mathjs can execute inside a generation.

`createNoteSnapshot` captures result payloads in a closure. Its public API contains calculation descriptions, diagnostic/dependency copies, `metadataSymbols`, `symbolsAt(offset)` and `format(calculationId,rowIndex)`. Each data-bearing access returns a fresh graph. Metadata symbol descriptions come from this generation's initialized seeds and support unfinished suggestion contexts without evaluating metadata again. Matrix inspection descriptions contain dimensions and indexed nonzero entries; omitted entries are zero. No public snapshot contains a populated scope, executable math function or native Unit. Formatting uses the shared ResultFormatter retained with the original engine. Formatting exceptions are returned as presentation diagnostics and cannot erase successful calculation bindings.

Internal function/opaque descriptions have private WeakSet ownership. Their plain public descriptions do not carry that ownership. User math objects with fields such as `kind: "numerals-function"` remain ordinary objects, including inside collections; field names alone never authorize special formatting.

`recordSymbolCheckpoint` records data-only symbol descriptions immediately at a source position. Snapshots select preceding globals and the current calculation's locals, including the successful prefix of a block that later failed. Reserved previous/total/reference bindings are excluded; ordinary user names with underscores remain available. Checkpoints replace preceding bindings rather than merging deleted locals/globals indefinitely. They do not enable forward references.

Rows carry their own insertion eligibility and reason. Dataview presence or pending status does not disable an independent constant/native result. The snapshot's `canInsert` is only an aggregate indicating that at least one row is eligible; G must use the target row's eligibility and all source transaction guards. Calculation presentation data includes captured block language, raw rows, blockInfo, transparent row indexes, format overrides and mapped insertion-directive spans. Each directive retains its entire expected token and, when present, its exact stored-value text and spans. An empty stored value has an empty projection span and no contributing physical span; consumers can replace the verified complete wrapper. Surfaces can preserve renderer behavior through this pure data and `format` without re-evaluating math or resolving references again.

Presentation replacement is a service operation (`reformatNoteSnapshot`), not a callback accepted by the surface-facing snapshot. It checks engine identity and retains the same backing results. An engine change requires a new evaluation generation.

## Generation and subscription contract

`NoteEvaluationService` is a host-independent coordinator around a capture/evaluation adapter. The adapter synchronously captures all source, metadata and evaluation settings before its first asynchronous step. It must construct a new session for each evaluation generation and retire private executable state after producing the snapshot. It must not reuse a populated old scope.

`NoteGeneration` records buffer identity, optional file path, source revision and complete source text, metadata/dependency revisions, evaluation-settings revision and runtime generation. The cache key includes every field, plus actual engine identity. Full source text is retained in the key even when a provider incorrectly repeats a source revision. Evaluation settings and metadata/dependency providers must advance their revisions whenever their mathematical input changes. Formatting, selection, cursor and viewport changes are excluded from this key.

`request(input)` shares pending work for an identical generation. A newer request aborts the previous generation; a stale completion or rejection resolves without a snapshot and cannot publish current state. Each `subscribe(sourceId,listener)` call owns an independent registration and returns an idempotent unsubscribe, even when callbacks are identical. `current` returns pending, ready or error state. One failing subscriber or error reporter cannot interrupt another surface. Publication checks both current state and active registration before every notification, so removed subscriptions are skipped and a subscriber that changes the generation cannot cause later subscribers to receive stale ready/error output after newer pending state.

`updatePresentation` replaces the formatter over the same backing values, including while evaluation is pending, without calling the evaluator. `invalidate` retires the cache entry and aborts pending work; host adapters request a new complete generation after source or dependency changes. `dispose` aborts all pending work and drops subscriptions. None of these operations writes source or touches a vault.

The concrete service treats the pending-to-unverified deadline as a status change when both states use identical captured native metadata. Its controlled internal snapshot operation retains private result data and the latest formatter, replaces the pending diagnostic, and publishes a fresh ready snapshot identity without changing the mathematical generation or repeating evaluation. Pending evaluations apply the status change to their one eventual result; timer expiry never retries an error. Real source, metadata, projection, dependency, settings or engine changes still require a new evaluation. Before applying any proposal, G must verify that `service.current(sourceId).snapshot === capturedSnapshot` as well as the source and runtime safety guards. This identity check invalidates older readiness and presentation snapshots without adding counters to the mathematical key.

`captureNoteEvaluationInput` indexes the entire authoritative buffer and synchronously captures native YAML, eligible Dataview fields, reference inputs, preprocessing rules and the runtime. A configuration error or ambiguous extraction blocks all mathematics, including metadata initialization. Typed reference records carry their original text, occurrence/relative span and originating engine identity. Runtime or text mismatches produce a dependency diagnostic, and conflicting duplicate captures are rejected. Values and provenance use the same exact reference occurrence. The trusted host must capture that table for this generation's source path and metadata/dependency revisions; record fields do not authorize reusing a stale asynchronous lookup. Reference dependencies in snapshots include physical source spans; preprocessing maps remain relative to the calculation's expression projection.

`evaluateNote` creates a fresh stable session and adapts the existing block and inline evaluators. It initializes dollar metadata once in a metadata environment, ordinary metadata in each calculation, and processes every indexed occurrence in physical order. Ordinary metadata initialization commits local bindings without republishing dollar writes over preceding source assignments. It records results immediately, preserves physical blank rows and formatting transparency, and retires executable scopes after constructing the snapshot. It neither reads host caches during evaluation nor evaluates a successful prefix again.

Mathjs engine effects can outlive a source generation. `runtimeProvenance.ts` keeps only uncertainty flags, labels and a monotonic safety epoch in a WeakMap keyed by engine. A broad uncertain `config` or dynamic/native effect can change even literal arithmetic; this uncertainty persists across notes and source revisions using that engine. Classification walks public mathjs syntax nodes rather than reproducing callable syntax in the extension scanner. A narrowly recognized `createUnit` effect can leave independent primitive arithmetic eligible. Passive reads and deferred declarations do not themselves mutate engine safety. Unknown opaque calls remain conservative. The legacy/reference metadata evaluators also observe before execution and record possible effects in `finally`, including failed or rejected reference values. A fresh runtime or plugin reload clears the state; reevaluating source does not.

Each driver row captures `insertion.runtimeSafetyEpoch`. G must call `isRuntimeSafetyCurrent(capturedEngine, row.insertion.runtimeSafetyEpoch)` at final application, in addition to row eligibility and source/input/occurrence guards. This rejects proposals from an earlier row or retained snapshot after a later unsafe effect on the same engine. Frozen `canInsert` is insufficient by itself. Missing epochs are not proof of safety. Safety changes do not trigger a source replay or an automatic reevaluation loop.

The fake-host service tests exercise complete-text identity, identical pending requests, buffers sharing a path, metadata/dependency/settings/runtime changes, obsolete asynchronous success and failure, disposal, capture ownership, presentation-only updates and reentrant subscriber replacement. The concrete driver tests exercise source order and generation ownership using mathjs. They do not establish Obsidian lifecycle behavior.

## Remaining gates

Source extraction is validated against I's accepted Obsidian 1.13.7 Linux observations for 95 fixtures, with F's explicit conservative source policies documented in `source-index.md`. This bounded evidence does not establish G surface integration, installed-candidate acceptance or other platforms. Dataview projection provenance is separate from event/mtime/index invalidation, as described in `note-metadata.md`; a result depending on an unverified projection cannot authorize automatic insertion. G must additionally validate editor identity, source and input generations, expected text, exact mapped spans and host occurrence identity before a transaction. A detached snapshot is not itself permission to write source.

Scope binding rollback remains narrower than arbitrary native side-effect rollback. Mutations inside opaque objects/closures and engine-level operations such as `createUnit` may survive a failed row within a generation. See `evaluation-scopes.md`; #175 remains open. No public raw-value wrapper or successful-prefix replay is introduced to imply stronger rollback.
