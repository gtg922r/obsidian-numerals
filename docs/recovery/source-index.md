# Full-note source index

`src/evaluation/sourceIndex.ts` indexes a complete authoritative source revision with the standalone `@lezer/markdown` 1.7.2 parser, GFM structure, a footnote composite extension and an Obsidian exclusion adapter. It does not read an editor view, visible syntax ranges, metadata, the DOM or a vault. It does not evaluate math or expand embeds.

## Inputs and outputs

`indexNote({sourceId, revision, path?, text}, policy?)` returns ordered block/inline calculations, original UTF-16 spans, line starts, exclusion regions, diagnostics and suggestion contexts. `sourceId` identifies the source buffer; `path` is separately retained and is not an editor identity. Occurrence IDs include source identity, supplied revision, kind and source span. Identical source text at two positions produces two occurrences. Callers must change `revision` when changing `text`; the evaluation cache must additionally key on complete captured text and its other inputs.

Fence matching lowercases the exact first whitespace-delimited info token and accepts `math`, `math-plain`, `math-tex` and `math-highlight`. Case variants and trailing attributes match the accepted native callbacks; `mathematics` does not. `rawInfo` retains the original complete info text and `language` is canonical lowercase. The default inline triggers match the existing settings (`#:`, `#=:`, `#$:`, `#$=:`). Consumers should supply the active settings' trigger table and `inlineEnabled`. Empty triggers disable their modes, the longest matching trigger wins, and exact duplicate nonempty triggers are disabled with a diagnostic.

A block stores physical body rows, including blank rows, alongside its complete projection. A row records its complete physical source line, separate original line ending and projected expression text. The last separator before a closing fence is not an additional body row. Empty fences have zero body rows; a fence with one blank body line has one empty row. Evaluation should consume `rows` rather than infer row count by splitting projected text. Bare and ordinary list unclosed fences retain the standalone parser's bounded extent and an explicit unclosed diagnostic. Quoted-tab fence openers and unclosed quote fences have an ambiguous host boundary. They set `evaluationBlocked: true`, withhold all calculations and suggestions in the note, and emit `ambiguous-container`. The existing guard also withholds unclosed fences whose container contains tabs. These checks run for every fence language, including non-Numerals and unlabelled fences: a prematurely ended ordinary fence can expose a fake Numerals inline expression in its body. Evaluators must skip all math, including metadata expressions, when `evaluationBlocked` is true. Use spaces for container indentation and close quoted fences explicitly. Some potentially valid ambiguous containers remain conservatively withheld until their bounds are proven.

An inline stores both its projected code content and `expression`, the projection with only the matched trigger removed. Source whitespace is retained for evaluation; `.trim()` is used solely to reject empty expressions. Matching requires a complete real code span, including its exact backtick delimiter lengths. The projection follows code-span rules: line endings become spaces, container prefixes are removed, and exactly one paired ASCII space is removed when content is not entirely spaces. Backslashes and entities inside code remain literal. A partially typed span belongs only to `findSuggestionContext(index, cursor)` and never becomes a calculation, exported binding or insertion proposal.

## Original-source mappings

`src/evaluation/sourceProjection.ts` represents each transformation as ordered source/target segments: copies, newline normalization, removed prefixes/padding and partial-tab expansion. All offsets count UTF-16 code units; astral characters count as two. The original source is never normalized in place. Parsing normalizes CRLF and lone CR to LF only in private parser input. A monotonic boundary table maps every normalized UTF-16 offset to the original buffer. The public Lezer tree builder reconstructs the same node types and hierarchy with original coordinates at one adapter boundary, before exclusions, container handling or extraction. Source text, physical rows and original line endings remain intact; no whitespace substitution changes Markdown structure.

`sourceSpansForRange(projection, start, end)` returns contributing original spans. A range covering two quoted rows can have two separated source spans; it must not be replaced using their bounding extent. `contiguousSourceSpan` returns a conservative single-span candidate only for nonempty, contiguous copied text. It rejects normalized newlines, expanded tabs and ranges crossing removed markup. It is not an insertion authorization: G must still verify editor identity, path, all source/metadata/settings generations, expected text and host occurrence binding before an editor transaction.

Container projections preserve quote/list/footnote ancestry and remove fence indentation with four-column tab accounting. A content tab following a quote marker is retained as an actual copied tab, matching native extraction. Tabs used by further container indentation retain explicit removal/expansion mappings; later container markers consume their preceding indentation before projecting content. Original physical rows still include all container characters. The expression projection can subsequently be composed with D's preprocessing/reference mappings; preprocessing offsets must not be interpreted directly as file offsets.

The expression scanner's `readInsertion(source, start)` returns the complete single-line wrapper span plus `contentSpan`, `expressionSpan` and optional `valueSpan`, all in the supplied source's UTF-16 coordinates. `valueSpan` excludes `::` and the outer closing bracket; an explicitly empty stored value has a zero-length span. Scanner insertion tokens retain these spans in `token.insertion`. The reader balances nested brackets, parentheses, braces and escaped strings without interpreting stored bytes or changing canonical serialization. It rejects incomplete, mismatched or multiline wrappers. Complete cross-note references inside the expression are opaque atoms, including punctuation in their note labels. Reference capture visits only the expression span; quoted text, comments and stored result values remain protected. Unwrapping, reference binding and directive normalization compose their maps back to the complete original wrapper. G must apply projection mappings and source-generation checks before using these spans for a transaction.

## Exclusion precedence

The adapter scans in lexical order against standalone structural code regions. Code opened first is opaque, so `%%`, HTML, dollar characters and wikilink text inside a math fence or code span remain literal expression input. An already-open comment, math region, structural HTML block, raw HTML code element, image, wikilink or embed suppresses apparent code inside it. Structural inline HTML tags mask their attributes while genuine Markdown code spans in ordinary inline element contents remain eligible. Markdown link labels remain eligible; image alt text and link targets are opaque. Footnote definitions are parsed at their physical source location, including four-column continuations and fences; rendered footnote relocation does not change evaluation order.

Frontmatter starts at the first line with optional BOM and `---`, ends at `---` or `...`, and supports LF, CRLF and CR source line endings. An unclosed header is excluded through EOF with a diagnostic; cached metadata must not reintroduce calculations or metadata from that region.

Excluded source is replaced only in a private parser input with same-length non-whitespace placeholders. Whitespace masking would invent an indented code block after a hidden image/comment at line start. Reparse after exclusions prevents a hidden fence from defining later source structure. Passes are bounded; if the adapter cannot converge in eight passes it sets `evaluationBlocked`, withholds calculations/suggestions and emits a diagnostic. The original source and mappings remain unchanged. Structural HTMLBlock extent is authoritative, including content after a closing tag until the Markdown block ends. Raw elements nested inside an ordinary HTML block also remain opaque through their closing tag, even across a blank-line boundary; missing raw closing tags exclude through EOF with a diagnostic. Raw `code`, `pre`, `script`, `style` and `textarea` elements are nonvoid; a slash in an opening tag does not close them. Tag scans skip attributes, comments and CDATA. The adapter does not treat arbitrary DOM `<code>` elements as Markdown calculations. Single-dollar math is bounded by the standalone parser's containing prose region, so CR line endings and empty quoted paragraphs cannot make it swallow a later calculation across a paragraph boundary.

An embed is recorded as an excluded source region. The evaluation/host layer must evaluate the target note's complete authoritative source generation, then project its selected occurrences into each displayed embed. The target's globals never enter the embedding note's scope. This index neither recursively expands source nor infers source identity from equal text or DOM order.
