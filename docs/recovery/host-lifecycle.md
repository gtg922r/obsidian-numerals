# Host lifecycle (Package C)

`HostEventHub` owns one subscription set for the plugin: native metadata `(file, data, cache)`, Dataview metadata `(type, file, oldPath)`, late Dataview readiness, vault create/delete/rename, and E's typed settings changes. Both metadata sources remain subscribed independently of Dataview's current availability. A hub releases host listeners when its last consumer leaves, and plugin unload cancels consumer work before disposing the host subscriptions. Each subscription has independent cleanup, even for identical callback functions. Nested signals queue behind the current delivery so rename order stays causal. Events are invalidation signals, never proof of a particular source or metadata generation.

Block ownership uses a WeakMap keyed by the actual rendered element plus an explicitly disposable active set. Identical siblings remain separate calculations. The same element/source callback reuses its child without reevaluation or extra listeners; a changed callback source refreshes it. A new host context replaces the child so the previous context cannot unload the replacement. Each MarkdownRenderChild releases its event subscription and click handler. Render failures show a concise diagnostic instead of escaping the host callback. Source-note rename updates the occurrence's local context and click destination.

Reading inline code elements retain their original source and their own render-child ownership, including unresolved references and currently disabled/unmatched triggers. A section coordinates its existing local scope and previous-result chain; duplicate callbacks find element ownership before examining transformed DOM. Only DOM actually rendered by Numerals is restored; unmatched or disabled code retains other plugins’ nested markup. Host replacement of an owned element’s content becomes new source, while unchanged Numerals output remains tied to its retained input. Settings changes restore disabled/retargeted source predictably. A removed child leaves its section, and its last child releases the section subscription and queued work. This does not establish full-note ordering across sections; G replaces section evaluation with F snapshots.

`affectsOccurrence` refreshes source metadata changes and resolved dependencies. Unresolved dependencies remain subscribed. File topology changes conservatively invalidate reference-bearing occurrences because link resolution and relative-name precedence can change. Dataview readiness invalidates all consumers. E's settings effect distinction remains intact; evaluation changes clear the legacy scope cache, while suggestions do not refresh calculations.

The CodeMirror view plugin subscribes while in Source mode, keeps widgets hidden there, and marks inputs dirty. Every update reads the actual Live Preview state field, including effect-only mode transitions. Host signals coalesce into a deferred state effect; no host callback recursively dispatches during a CodeMirror update. Destroy and plugin unload cancel pending dispatches. Combined document/viewport changes rebuild the visible projection instead of retaining stale ranges. Each visited syntax range is handled once.

Click navigation uses the rendered element's document/window for Node checks, accepts Text-node parents and SVG descendants, and only moves/focuses the editor cursor. Existing file-only editor lookup and approximate source columns remain G follow-ups; this package does not add insertion writes.

## Explicit integration boundary

C continues the existing evaluators and rendering strategies. Full-note order, offscreen/selected predecessor evaluation, zero-evaluation selection/scroll projection, presentation-only raw snapshot reformatting, generation-safe reference freshness, and transactional insertion remain F/G work. A presentation setting currently requests a renderer refresh, which can evaluate math through the legacy pipeline. Legacy source caches are conservatively invalidated on host input changes; they are not a replacement snapshot cache. No new evaluator or production release is introduced.

Tests exercise element ownership and child/plugin unload, independent native/Dataview event signatures, late Dataview readiness, missing-reference creation/deletion, source metadata, vault rename, settings disposal, queued-work cancellation, actual CodeMirror StateFields and effect-only mode transitions, and iframe/Text/SVG navigation. CodeMirror tests supply a fixture for Obsidian inline syntax ranges; parser compatibility belongs to F and installed-host validation to I. No Obsidian launch or live-vault write is part of this package.
