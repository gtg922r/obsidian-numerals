# Expression scanning and reference contracts (Package D)

Mathjs remains the parser and evaluator. `expressionScanner.ts` supplies a narrow lexical extension pass used by block, inline, and metadata routes. It recognizes protected strings (including escapes and expression-position single quotes), transpose, `#` comments, delimiter nesting, reference spans, complete numeric/currency candidates, and Numerals directives. It never reparses metadata values through formatted display text.

## Input rules

- Commas in calls, arrays, indexes, and objects remain mathjs delimiters, including in grouping parentheses nested within them. Use ungrouped numbers in those contexts: `max(1234, 5)`, `[1234, 5]`, `A[1, 234]`.
- Complete grouped literals normalize at top level or in ordinary grouping parentheses: `1,234.5 + 2`, `(1,234) * 2`, `(1+2)(1,234)`, `3! (1,234)`. Parentheses after symbols/index accessors remain calls; parentheses after computed results and postfix operators use mathjs implicit multiplication. A grouped integer has 1–3 leading digits (no leading zero), followed by three-digit groups. A decimal fraction and a complete exponent are supported.
- An explicit configured currency prefix identifies one amount even inside a list/call: `max($1,234.50, $2)`. `StringReplaceMap` now accepts `currencySymbol` and `currencyCode` alongside the legacy required regex/replacement fields. Complete scientific amounts retain their exponent. Legacy regex callers remain supported for existing non-scientific currency input, but cannot strip argument commas.
- Configured suffix amounts and standalone currency conversion symbols normalize to codes with full original-token mappings. Suffix forms preserve call/list/index commas (`[1,234$]` has two elements); currency characters within identifiers (`foo€`, `$price`) and property names (`{$: 2}`, `obj.$`) stay intact. Native quoted unit strings remain protected and use the private runtime aliases. Supplementary Unicode currency symbols use UTF-16 source offsets.
- Malformed candidates such as `1,0001`, `1,23`, `1,,234`, `1,234.56.7`, and incomplete exponents are left for mathjs to reject. No valid prefix is partially normalized. In `max(1,0001)`, the comma remains a delimiter and mathjs interprets `0001` as one.
- All normalization and Numerals directive discovery/replacement protects strings/comments, including `@prev`, `@sum`, result directives, emitters, and formatting directives. `@createUnit` has no special preprocessing behavior; unit collisions remain errors. Same-note metadata functions remain supported. Insertion wrappers unwrap before directive translation, so `@[@prev]` and `@[@sum::3]` retain both their mathematical meaning and original insertion spans; displayed input keeps the directive label.

## Typed values and binding ownership

`resolveCrossNoteReferences(source, app, sourcePath, settings, processors, occupiedNames?)` returns `bindings`, `bindingNames`, `sourceMap`, `dependencies`, `referencedPaths`, `warnings`, and the first resolution `error`. It attempts every occurrence, including references after a failed one. Callers must pass their existing scope as `occupiedNames`; the block and inline adapters do so.

Each successful reference becomes an opaque mathjs symbol with a cloned supported value. The binding table belongs to that calculation; names are allocated monotonically and checked against original source and occupied scope. `createReferenceScope` wraps ordinary variables and that table. Functions defined by the calculation retain that table; later calls do not install a shared `__ref0` table. Reads clone with public `math.clone`, so mutable matrix/unit/complex values cannot modify referenced metadata. Numbers, booleans, strings, bigint, BigNumber, Fraction, Complex, Unit and arrays/matrices of supported values are accepted. Functions, arbitrary objects and ResultSets are excluded. Arrays originating directly from metadata select their last entry before evaluation; a string expression such as `"[1,234]"` evaluates to a matrix.

`evaluateWithReferences` uses mathjs ASTs to reject assignment targets, indexed assignments, function names, and parameters targeting a binding. The scope also rejects binding writes/deletes. Its size, iteration, lookup, forEach, and cloning agree. Ordinary set/delete operations write through to the caller scope. `clear()` explicitly fails when bindings exist; without bindings it clears ordinary scope. Tables do not leak internal keys into ordinary globals. Callers should treat returned tables as read-only.

## Original source and diagnostics

`MappedSource` contains `originalSource`, transformed `source`, and mappings with explicit `identity`/`replacement` kinds. `SourceSpan` offsets are zero-based UTF-16 offsets, end exclusive, relative to the expression/block. `applySourceEdits` composes ordered non-overlapping edits with prior mappings; extraction in F can supply an initial map. Identity segments map exactly. Replacement segments always map to the entire original token, even when source/generated lengths happen to match. A point inside a replacement maps to that token; a point in identity text maps to a point. At a shared boundary the segment on the right wins; EOF maps to original EOF. Invalid spans throw. This is diagnostic/extraction mapping, not permission to apply a source write: G still must validate source revision and exact expected spans/text.

`ProcessedBlock.sourceMap` and `InlineEvaluationResult.sourceMap` map the final normalized evaluation source. Original `rawRows` are retained for display/errors. Mathjs parser character offsets are translated through this final map. Successful display inputs restore exact reference identifiers; Plain, TeX and syntax-highlighted block rendering preserve reference labels without interpreting note names as expressions. Inline `processedExpression` is display input (references restored); its `sourceMap.source` is the evaluation source. Never evaluate restored display input directly. Canonical formatting and insertion serialization are unchanged.

## Dependencies and adapter boundaries

Each `ReferenceDependency` includes original start/end/fullMatch, sourcePath, noteName, propertyPath, optional resolvedPath, and status (`resolved`, `missing-note`, `unavailable-property`, `invalid-value`) with an optional error. `referencedPaths` remains the unique resolved-path projection for existing adapters. Missing properties and invalid values retain their file path; missing notes retain their link name and source path for later re-resolution. Opt-in frontmatter and Dataview scalar/array interpretation remain in force; computed cross-note globals/functions are excluded.

Blocks preserve results before the first erroneous row and stop that block there. Inline errors throw `ReferenceEvaluationError` carrying originalInput, final sourceMap, optional sourceSpan, referencedPaths, and the full dependencies. Both inline adapters now retain resolved dependency paths when evaluation fails. Block results and inline success results expose full dependencies. C must subscribe to native/Dataview events correctly and consume unresolved-note records for create/rename recovery; this PR does not claim host event freshness or whole-note ordering. F/G own generations, note indexing, note-local scope replacement, and verified transactional writes. No live vault artifacts were changed.
